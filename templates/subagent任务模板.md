# 研究型子任务模板（Step 5 采集时并行 fan-out 用）

> 把「政策/行业动态/一级市场融资」这类 web 检索型任务，交给子 Agent 并行执行，
> 子 Agent 只回**结构化数据**（严格按下方 schema），主 Agent 负责验真 + 写入月报。
> 目的：把「临场起意派子 Agent」固化成可复用模式，输出格式一致。

---

## 一、何时 fan-out

当数据单元满足以下条件时，用子 Agent 并行：
- 属「事件型/检索型」（政策、行业动态、一级市场融资），而非「名单型」（IPO 在审，需交易所官网一手数据）；
- 单一 web 检索即可覆盖，不需要交易所直连；
- 独立于其他单元（无先后依赖）。

## 二、子 Agent prompt 骨架（直接套用）

```
你是数据采集助手，任务是检索「{时间范围}」{行业}行业的{数据类型}，供行业月报使用。

背景：当前时间约{YYYY-MM-DD}，{时间范围}是「上个月/上月」。请用 web_search（可多次）检索。

严格纪律：
1. 只返回【真实可溯源】的事件，每条必须给出日期与来源；找不到的不要编造。
2. 按「事件日期」升序排列。
3. 每条严格按下方字段输出（一行/一条，字段用 | 分隔）：
   {字段列表，见下}
4. 做 4-6 次 web_search，尽量覆盖 {层面}。
5. 不要写月报正文，只返回结构化清单；末尾附「采集说明」+「缺口清单」。

最后输出格式：
### 采集说明
- 共采集 N 条，日期覆盖 {起}—{止}
- 缺口：{哪些板块没搜到}

### 数据清单
| {字段名1} | {字段名2} | ... |
| --- | --- | --- |
| ... |
```

## 三、各类型的字段 schema（子 Agent 必须按此列输出）

**政策动态**：`日期 | 发布主体 | 政策/文件名称 | 要点摘要(含关键数字) | 来源(机构+日期)`

**行业动态事件**：`日期 | 公司/主体 | 事件分类 | 事件标题 | 详情(2-5句含关键数字) | 来源`

**一级市场融资**：`融资方 | 交易轮次 | 融资金额 | 投资方 | 交易日期 | 来源`（金额口径：未披露/数千万元/数亿元/数亿美元/XX亿元/XX万元/XX万美元）

## 四、主 Agent 回接时的验真动作（必做）

1. 抽查 2-3 条，用来源 URL 反查标题是否真实存在；
2. 剔除「待核验」条（子 Agent 自己标注的），或补一次 web_search 确认；
3. 按 `config/口径字典.yaml` 给每条打「赛道分类」；
4. 金额/法人等字段，能交叉验证的按 `config/权威源映射.yaml` 降级链补核。

## 五、边界

- 子 Agent **不负责**：写月报正文、判断赛道口径、调用需要凭证的 MCP（iFinD/qcc/IT桔子）；
- 子 Agent 只做 web 检索 + 结构化回传；所有「判定/写入/交叉验证」都在主 Agent。

---

## 六、独立审核子任务（盲审规范 · P0）

Step 8 的独立审核必须是**盲审**——审核者只看「产出物 + 源文件」，**不看**主 Agent 的
溯源推理过程与自评结论，避免锚定效应（看了主 Agent 的“已核验”结论，审核就成了复读）。

**允许输入（仅此两类）**：
1. 新月报 docx（成品）；
2. 下载资料/ 源文件目录（原始证据）+ 网页快照（如有）。

**禁止输入（防锚定）**：
- 溯源.jsonl、变更摘要.md、数据流审计产出.md、主 Agent 的任何中间推理/门禁输出；
- 旧月报之外的历史溯源文件。

**子 Agent prompt 骨架**：

    你是独立审核员，对一份行业月报做对抗性盲审。
    输入：① 新月报 docx；② 源文件目录（CSV/快照）。
    你【没有】也【不许索要】作者的溯源文件与自评结论——请只依据源文件独立复核。

    任务：
    1. 从月报中抽取 10-20 个关键数字（家数/金额/比率），自行到源文件中找到对应值核对；
    2. 检查正文结论与表格数据是否互相矛盾；
    3. 检查「无法获取」标注是否真实（源文件里其实有没有）；
    4. 每个问题给出：位置 / 月报值 / 源文件值 / 严重度。

> **结果落盘（P1-4）**：子 Agent 完成后必须先把完整结果写入 runs/<run-id>/sources/子任务-<名称>.md，再在返回消息中给出摘要——主 Agent 从文件读取，杜绝会话中断丢结果。
>     > **盲审自检清单（随 prompt 下发，2026-09 沉淀自各期实测）**：
> 跨月去重（公告日vs转载日）｜上月口径残句（以「上月」为主语的数据段/段首无主语残句）｜vMerge 合并伪影（序号跳号/错配）｜续表表头与孤立表头｜正文计数=表行数｜日期口径差一天须注明｜金额单位混排｜通道降级声明可见性｜run 结构与图注｜残行清理｜残句删除用 in 不用 startswith｜「无法获取」标注真实性抽查。
>
输出（严格按严重度分级）：
    ### 阻断级（数据错误、来源虚构、结论与证据矛盾）— 必须修正后才能交付
    ### 建议级（口径表述含糊、缺脚注、命名不规范）
    ### 提示级（可读性、格式微调）
    末尾附「复核覆盖率」：共核对了 N 个数字，占全文关键数字约 X%。

**回接规则**：
- 阻断级 > 0 → 回到 Step 5/6 修正，修正后**换一个新的审核子 Agent 复审**（避免同一审核者自我确认）；
- 审核意见按原分级写入《独立审核意见.md》；子 Agent 通道失败时按 SKILL.md D 节降级 mainagent，
  并在意见开头显式标注「独立性受损：盲审降级为主 Agent 自查」。
